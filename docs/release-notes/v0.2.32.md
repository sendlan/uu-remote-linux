修复端口映射在 ICE 瞬断恢复后被续房拆掉、信令卡死后长时间假在线，以及查看器 CLI 的指针偏移与滚轮。本仓库的构建在此基础上新增 LoongArch（龙芯）支持。/ Fixes port-mapping teardown after ICE recovery, stalled signaling, and viewer CLI pointer/wheel input. This repository additionally adds LoongArch support on top of v0.2.32.

### 新增 / Added
- **LoongArch64 支持**：提供 `loong64`（Debian/Loongnix 架构名）与 `loongarch64`（AOSC 架构名）两种 deb 包，二者为同一 ABI 2.0 二进制。已在 Loongnix 25 / 3A6000 上实测：X11 采集、VAAPI 硬编码（RX 580）、音频采集、文件传输、终端均正常。
  LoongArch64 support with both `loong64` (Debian/Loongnix) and `loongarch64` (AOSC) deb packages — the same ABI 2.0 binary. Tested on Loongnix 25 / 3A6000 (X11 capture, VAAPI encoding, audio, file transfer, terminal).
- **VAAPI 编码器**：色彩空间转换与缩放移到 GPU（`scale_vaapi`），降低编码 CPU 占用。
  VAAPI encoder: colorspace conversion and scaling now run on the GPU.
- Release workflow 通过 QEMU + Debian loong64 容器构建 LoongArch 包，随正式发布一起上传（与 x86_64 / aarch64 相同流程）；升级 vendor 的 webrtc/nix 组件以支持 loongarch64 构建。
  The release workflow builds LoongArch packages under QEMU (Debian loong64 container) and uploads them with every release; vendored webrtc/nix components upgraded for loongarch64 builds.

### 修复 / Fixed
- **ICE 瞬断恢复后连接被拆（#109，感谢 @sinoyster 的细致分析）**：WebRTC 的 ICE 状态回调读到的是占位 DTLS 对象，ICE `Disconnected → Connected` 恢复后 PeerConnection 停在 `New`，15 分钟续房把仍在使用的端口映射当成空闲，拆房并断开所有映射 TCP 流。现在恢复后会回到 `Connected`。
  After a brief ICE drop the peer state settled on `New` instead of `Connected`, so the idle room renewal tore down live port-mapping streams.
- **信令投递卡住时心跳检测失效（#104，感谢 @RiverOnVenus）**：事件队列阻塞时 Engine.IO 超时不再执行，主机可能带着半关闭的连接“在线”数小时。现在有独立看门狗、发送超时和关闭超时。
  Heartbeat detection keeps running when event delivery stalls; the host reconnects instead of staying half-online.
- **查看器 CLI**：16:10 等非 16:9 主机的指针按内容区域映射，不再内偏（#107，感谢 @liuyanghejerry）；鼠标滚轮/触控板转发为滚动（#108，感谢 @liuyanghejerry）。
  Viewer CLI: pointer mapped to the content rectangle of the padded canvas; mouse wheel forwarded.

### 验证范围 / Validation
单元测试与 CI；#109 的 ICE 恢复场景尚未实机复现，欢迎反馈。LoongArch 包已在 Loongnix 25（3A6000）实机验收。
